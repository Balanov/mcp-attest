How it works

01
POLICY
Who may call what, and how each identity presents itself: headers or environment.
02
CONNECT
One session per identity over stdio or Streamable HTTP. JSON-RPC spoken directly, no SDK.
03
CALL
Every identity against every tool, with arguments derived from the tool's own schema.
04
FINDINGS
A blocking exit code, SARIF for code scanning, and a hash-chained evidence bundle.

Twelve rules

AT-AUTHZ-001
policy per identity
the server allows what your policy denies
AT-AUTHZ-002
cross-user objects
a valid id belonging to another principal
AT-TOKEN-001
tokens validated
a malformed, tampered or expired token gets through
AT-POISON-001
no hidden instructions
instructions smuggled into tool metadata
AT-DRIFT-001
no manifest drift
a tool added or changed after approval
AT-SECRET-001
no secrets in output
a credential in the tool output
AT-FAILCLOSED-001
fail closed
a call executed with missing arguments
AT-INJECT-001
no injected output
instructions aimed at the model in a result
AT-SINK-001
guarded sinks
model input reaching a shell, a file or a URL
AT-SCHEMA-001
strict schemas
untyped, unbounded or free-form arguments
AT-APPROVAL-001
declared risk
a state-changing tool with no risk declared
AT-ERROR-001
clean errors
stack traces and internal paths in errors

Use it in CI

1
Write the policy
attest init --command "python my_server.py" scaffolds one from the live tool list. Default deny, one entry per identity.
2
Point it at the server
stdio or Streamable HTTP. The harness connects as each identity and calls what the policy allows and forbids.
3
Gate the build
The action fails on critical or high findings, and SARIF lands in code scanning next to the rest of the repository.
4
Keep the evidence
A hash-chained, optionally signed bundle per run: request, response, identity, decision, timestamp.
- uses: Balanov/mcp-attest@v0
  with:
    policy: .attest/policy.json
    command: "python my_server.py"
    sarif: mcp-attest.sarif

Why it exists

OWASP · MCP Security Testing Guide

"Security controls should be executable tests, not only checklist items." Its minimum automated test set starts with the authorization matrix: every tool, role, scope, tenant and object, including ids owned by another user.
agentgateway, own evaluation · October 2026

"Turning a policy on is not the end of the job: send real calls and check."
NSA / CISA · MCP Security Design Considerations

"Without these traceable audit logs, incident response and accountability become significantly difficult, especially in multi-tenant environments."

MCP testing is crowded — mcp-assert, mcp-fence, mcp-fuzz, MCP-Scan, promptfoo, mcpsnoop, mcp-conformance. What none of them does is the authorization matrix and token validation the OWASP guide puts first. This one does, offline and deterministically. Full comparison →
